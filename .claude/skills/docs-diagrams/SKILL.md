# Documentation Diagrams

The diagrams in `docs/images/diagrams/*.svg` are generated by [diagrams.py](diagrams.py), next to this file. The generator is the
source of truth: never edit the SVGs by hand. Change or add the diagram function, regenerate, and commit the script and the SVGs
together.

```shell
python .claude/skills/docs-diagrams/diagrams.py                                # all diagrams
python .claude/skills/docs-diagrams/diagrams.py inbound-batch chunk-basic      # only these
python .claude/skills/docs-diagrams/diagrams.py --preview "$TEMP/diagrams.html"
```

Regenerating all the diagrams without changes to the script must leave `git status` clean.

## Style

The diagrams explain one idea at a glance. Keep them simple: a handful of elements, no implementation details, and let the
`figcaption` and the text around the figure explain the rest.

- **Messages** are colored rounded squares labeled 1–4 (`Svg.cell`). Each number keeps its color (`COLORS`) through the whole
  diagram, so that the reader can follow a message from producer to consumer. Encrypted messages are gray with a padlock
  (`Svg.lock`), failures get a red badge.
- **Columns** usually go from left to right: producer, topic, consumer. Each has a card (`.card`) and an uppercase label above it
  (`Svg.label`). Use `vertical_messages` and `row_messages` for the common cards.
- **Groupings** inside a card (batches, streams, lanes, a transaction) are dashed boxes (`.group`) with a small uppercase label
  (`.sub`).
- **Flow** is a gray arrow (`Svg.arrow`, or `Svg.path_arrow` for curves).
- **Text** is short and in American English. Uppercase labels for names (`TOPIC`, `BATCH 1`), sentence case only for the few
  descriptive texts (`.text`).

The site has a light and a dark theme (dark by default), and an SVG shown with `<img>` can't follow the page theme. The
diagrams are therefore theme-neutral: transparent background, semi-transparent gray cards and mid-tone colors that read on both
`#f6f8fb` and `#161b22`, the figure backgrounds set by `figure img` in `docs/_templates/silverback/public/main.css`. Don't
introduce colors that only work on one of them, and don't rely on web fonts (the SVG can't load them, so `FONT` falls back to
the system fonts).

Every diagram has a `title` and a `desc` (the accessible name and description) that describe what it shows.

## Adding a Diagram

1. Add a function decorated with `@diagram("<file name without extension>")` that builds and returns an `Svg`. Reuse the helpers
   and the proportions of the existing diagrams (38px messages, 66px-high row cards, labels at `y=26`, cards from `y=40`, a
   24px margin) so that all the diagrams have the same scale. Size the canvas to the content.
2. Generate it with `--preview` and check both themes. Render the preview with a headless browser and look at the screenshot,
   for example with Edge on Windows (PowerShell):

   ```powershell
   Start-Process "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" -Wait -ArgumentList `
       "--headless=new", "--hide-scrollbars", "--user-data-dir=$env:TEMP\edge-diagrams", "--window-size=1700,2300", `
       "--screenshot=$env:TEMP\diagrams.png", "file:///$($env:TEMP -replace '\\', '/')/diagrams.html"
   ```

   Look for clipped cards (the canvas too small), overlapping text and inconsistent spacing.
3. Embed it in the guide, right after the introduction of the concept it explains:

   ```html
   <figure>
   	<a href="~/images/diagrams/<name>.svg"><img src="~/images/diagrams/<name>.svg" alt="<short description>"/></a>
       <figcaption><One sentence explaining what the diagram shows.></figcaption>
   </figure>
   ```

4. Remove the SVG of a diagram you delete, and its references in `docs/guides`.
